# 에너지 뉴스 트렌드 분석 CLI — 설계서

작성일: 2026-10-10 · 과제: AI Native Term Project `[Project B] AI 뉴스 트렌드 및 종합 분석 리포트`

## 1. 한 줄 요약

전기신문(electimes.com)의 에너지 뉴스를 **RSS와 크롤링 두 방법**으로 모아 SQLite에 원본(raw)과 정제본(clean)으로 나눠 저장한다. 이어서 AI로 기사별 요약과 기간·카테고리별 인사이트 분석을 하고, 차트와 리포트를 만들어 CSV·JSONL·Excel로 내보낸다. 모든 기능은 `python main.py <서브커맨드>` 하나로 실행한다.

```
fetch ──▶ raw_news ──clean──▶ clean_news ──summarize──▶ summaries
 (RSS·크롤링)  (받은 그대로)        (검증·정규화·중복 처리)        (기사별 AI 요약)
                                        │
                                        ├──analyze──▶ analyses (기간·카테고리 AI 분석)
                                        │
                                        └──report / export / list / show
                                             (차트 PNG, 리포트 MD/TXT, CSV·JSONL·XLSX, 조회)
```

### 2.4 크롤링 윤리와 저작권

- 실행할 때마다 `urllib.robotparser`로 robots.txt를 읽고, 금지된 경로는 요청하지 않는다.
- 요청 사이에 **2초 이상** 쉰다(`request_delay_sec`). robots.txt에 우리에게 해당하는 `Crawl-delay`가 있고 더 길면 그것을 따른다. 한 번 실행할 때 기본 수집량은 카테고리당 10건이고, `--since`로 기간을 주면 상한은 카테고리당 50건·목록 5쪽이다.
- 본문을 이미 받은 기사(raw에 crawl이 있는 기사)는 다시 요청하지 않는다. 다시 받아야 할 때만 `fetch --recrawl`을 쓴다.
- User-Agent에 학습용 프로그램임을 밝힌다.
- 사이트 저작권 정책(제2조)은 승낙 없는 복제·전송·배포를 금지한다. 그래서 다음을 지킨다.
  - 기사 본문은 **로컬 DB(`data/news.db`)에만** 저장하고, DB 파일은 `.gitignore`로 저장소에서 뺀다.
  - 공개하는 결과물(리포트, 내보내기 샘플)에는 제목, 링크, 직접 만든 요약·분석만 넣는다. `export --include-body`를 줘야만 본문이 들어간다.

### 2.5 API·RSS 방식과 크롤링 방식 비교 (과제 목표 1)

| 항목 | RSS | 크롤링 |
|---|---|---|
| 형식 | 정해진 XML 구조라 파싱이 안정적 | HTML 구조에 의존해서 사이트 개편 시 깨짐 |
| 내용 | 섹션 피드마다 최신 20건(전체 피드는 50건), 요약문만 있음 | 본문 전체, 지난 기사(쪽 넘김) |
| 분류 | 상위 섹션(에너지·탄소중립·전기경제)까지만 | 세부 카테고리(전력·태양광 등) |
| 부담 | 요청 1번에 20건 | 기사마다 요청 1번이라 느리고 서버 부담이 큼 → 지연 필수 |
| 정책 | 배포용으로 공개된 피드 | robots.txt·이용약관 확인 필요 |

이 프로그램은 두 방식을 보완적으로 쓴다. RSS로 최신 기사를 빠르게 찾고, 크롤링으로 본문과 세부 카테고리를 채운다.

## 3. 저장 구조 (SQLite `data/news.db`)

### 3.1 테이블

| 테이블 | 주인(역할) | 주요 컬럼 | 설명 |
|---|---|---|---|
| `raw_news` | 1 | id, source, method(`rss`/`crawl`), channel(피드 이름 또는 카테고리), url, article_key, payload(JSON), payload_hash, fetched_at, status(`new`/`cleaned`/`rejected`/`duplicate`), note | 받은 그대로 보관. UNIQUE(method, article_key, payload_hash)라 완전히 같은 내용은 두 번 쌓이지 않는다 |
| `fetch_log` | 1 | id, run_at, method, channel, requested, succeeded, failed, saved, message | 수집 실행 기록. 채널(피드·카테고리)마다 1행. requested·succeeded·failed는 HTTP 요청 수, saved는 새로 저장한 raw 수 (수집 성공률 지표에 사용) |
| `clean_news` | 1 | id, article_key(UNIQUE), url, title, body, body_source(`crawl`/`excerpt`/`none`), section, category, category_source(`site`/`keyword`/`default`), author, published_at, published_date, first_collected_at, last_collected_at, methods, status(`cleaned`/`summarized`/`summary_failed`/`no_body`), created_at, updated_at | 정제된 기사 1건 = 1행 |
| `summaries` | 2 | id, news_id, summary, keywords(JSON), model, input_chars, output_chars, created_at | 기사별 요약 (재요약하면 새 행, 최신 행 사용). keywords는 리포트의 키워드 TOP N에 쓴다 |
| `ai_errors` | 2 | id, task(`summarize`/`analyze`), target, error, attempts, created_at | AI 실패 기록 (실패해도 프로그램은 계속 진행) |
| `analyses` | 2 | id, date_from, date_to, category, article_count, article_ids(JSON), items(JSON), result(JSON), model, created_at | 인사이트 분석 결과 |

- `article_key` = 기사 ID(`idxno`). 주소에서 ID를 못 찾으면 주소를 정규화한 값의 해시를 쓴다.
- 날짜는 모두 한국 시간 `YYYY-MM-DD HH:MM:SS` 문자열로 저장한다.

### 3.2 raw와 clean을 나누는 이유 (과제 목표 3)

- **다시 처리할 수 있다.** 정제 규칙을 고쳐도 사이트에 다시 요청하지 않고 raw에서 clean을 새로 만들 수 있다(서버 부담과 차단 위험이 줄어든다).
- **추적할 수 있다.** clean의 값이 이상하면 raw의 원래 응답(payload)과 수집 시각·방법을 보고 원인이 수집인지 정제인지 가릴 수 있다.
- **역할이 나뉜다.** raw는 "받은 것을 그대로", clean은 "분석에 쓸 수 있게 검증된 것"만 담는다. 요약·분석·리포트는 clean만 읽는다.

## 4. 정제 규칙과 중복 처리

### 4.1 정제 규칙

| 규칙 | 내용 | 실패 시 |
|---|---|---|
| 필수 필드 검증 | article_key, url, title, published_at | raw.status = `rejected`, note에 이유 |
| 텍스트 정규화 | HTML 태그 제거(`<br>`·`</p>`는 줄바꿈), HTML 엔티티 복원(`&apos;` → `'`, 두 번 인코딩된 것까지), 연속 공백·빈 줄 정리, 바이라인(`[전기신문 OOO 기자]`, `OOO 기자 메일주소`)·저작권 문구 제거, 요약문에서 붙어 버린 문장 띄우기(`나온다.8일` → `나온다. 8일`, 소수점 `0.3GW`는 그대로) | — |
| 날짜 통일 | RSS `2026-10-10 09:42:45`, 기사 `2026-10-10T09:42:45+09:00`, 목록 `2026.10.10 09:42`, 표준 RSS `Fri, 10 Oct 2026 ...` → `2026-10-10 09:42:45`. 다른 시간대는 한국 시간으로 바꾼다 | 해석 불가 → `rejected` |
| 결측값 처리 | 기자 없음 → `미상` / 본문 없음(크롤링 본문이 50자 미만) → RSS 요약문 또는 목록 요약문으로 대체(body_source=`excerpt`), 그것도 없으면 `no_body`(요약 대상에서 제외) / 세부 카테고리 없음 → 아래 4.2 | — |

### 4.2 카테고리 정하기

RSS로만 받은 기사에는 세부 카테고리가 없다. 다음 순서로 정하고 `category_source`에 근거를 남긴다.

1. **site**: 크롤링한 목록 페이지의 세부 카테고리, 없으면 기사 페이지의 `article:section1`. 같은 기사가 RSS와 크롤링 양쪽으로 들어오면 크롤링 값을 쓴다. 단, config.json에 있는 세부 카테고리(10개)일 때만 쓴다. 설정 밖의 사이트 분류(예: `산업정책`, 칼럼 이름)는 2번으로 넘긴다. 사이트가 준 원래 값은 raw_news payload에 그대로 남는다(6단계 실행에서 칼럼 이름이 카테고리로 잡혀 10-10 변경).
2. **keyword**: config.json의 카테고리별 키워드(예: 태양광 → `태양광, 태양전지, 태양에너지`)가 제목에 있으면 그 카테고리. 여러 카테고리에 걸리면 걸린 키워드가 가장 많은 것(같으면 설정 순서).
3. **default**: 위 둘 다 아니면 `기타`.

### 4.3 중복 처리 정책 (`duplicate_policy`: `skip` | `upsert`)

- 같은 clean 실행 안에서 같은 article_key를 가진 raw는 먼저 하나로 합친다. 본문과 카테고리는 크롤링 값이 우선이고, 수집 방법은 `rss,crawl`처럼 함께 기록한다.
- 이미 clean_news에 있는 기사와 겹칠 때:
  - `skip`: 기존 행을 그대로 두고 raw를 `duplicate`로 표시한다.
  - `upsert`: 새 값으로 갱신하되, 비어 있지 않은 기존 값(본문, site 카테고리)을 빈 값으로 덮어쓰지 않는다. 요약은 유지하고 `updated_at`을 바꾼다.
- 정책은 config.json에서 정하고(기본 `skip`), `clean --policy`로 그 실행에만 바꿀 수 있다.
- raw 단계에서도 완전히 같은 내용은 두 번 저장하지 않는다(3.1의 UNIQUE). 그래서 같은 피드를 다시 받아도 clean에서 중복이 생기지 않고, 기사 내용이 바뀌었을 때만 새 raw가 생겨 위 정책이 적용된다.
- 정제 규칙을 고친 뒤에는 `clean --rebuild`로 raw 전체를 다시 정제한다(사이트에 다시 요청하지 않음, upsert로 갱신).

## 5. AI 연동 (과제 목표 4)

- 기관 API(OpenAI 호환 `/v1/chat/completions`), 모델 `gemini-3-flash`, `requests`로 직접 호출한다.
- 키·주소·모델은 `.env`(환경변수 `CODYSSEY_API_KEY`, `CODYSSEY_BASE_URL`, `CODYSSEY_MODEL`)에 둔다. config.json에는 **환경변수 이름**만 적는다(키 값이 설정 파일과 저장소에 남지 않게 하려는 것).
- 기관 API 제약과 대응:

| 제약 | 대응 |
|---|---|
| `response_format`(JSON 모드) 미지원 | 프롬프트로 "JSON 객체 하나만" 지시 + 출력 형식 예시. 응답에서 코드펜스·앞뒤 설명을 건너뛰고 첫 JSON 객체를 읽는다. 못 읽거나 필수 키가 없으면 "JSON만 다시" 문구를 붙여 재요청 |
| 사고 토큰이 `max_tokens`에 포함됨 | `max_tokens`를 보내지 않고, 길이는 프롬프트로 제한 |
| 긴 입력에서 간헐적 400 | 요약은 본문을 4,000자로 자르고 400이면 2,000자로, 분석은 기사별 내용을 300자에서 150자로 줄여 재요청 (더 줄일 수 없으면 같은 입력으로 대기 후 재요청) |
| 타임아웃·연결 실패·429·5xx | 2초·4초 대기 후 재요청 |
| 401·403(키 오류) | 재요청하지 않고 명령 전체를 멈춤 (남은 기사도 같은 이유로 실패하므로) |

- 위 재요청을 모두 합쳐 **한 건당 최대 3번**(`max_attempts`)만 호출한다. 무한 재시도는 하지 않는다.
- 끝내 실패하면 ERROR 로그와 `ai_errors`(작업, 대상, 마지막 오류, 시도 횟수)에 남기고 그 기사만 건너뛴다. 이 경우 clean_news.status는 `summary_failed`가 된다. 다음 기본 실행(`--unsummarized`) 때 다시 시도한다.
- 기사 1건마다 커밋하므로 중간에 멈춰도 그때까지 한 요약은 남는다.
- API 키 값은 요청 헤더에만 넣고 로그·오류 메시지·DB에 쓰지 않는다.

### 5.1 요약 (summarize)

- 입력: 제목 + 본문(최대 4,000자)
- 출력: `{"summary": "3문장 이내, 300자 이내", "keywords": ["...", "..."]}`. 수치와 고유명사를 유지하고 추측을 넣지 않는다.
- 응답 검사: summary가 비어 있으면 형식 오류(재요청). keywords는 공백 정리·`#` 제거·중복 제거 후 최대 5개.
- 대상 선택: `--unsummarized`(기본, cleaned·summary_failed) / `--all`(본문 있는 기사 전체) / `--id`. 이미 요약된 기사는 `--all`·`--id`에서도 건너뛰고 건너뛴 수를 알린다. `--force`면 다시 요약해서 summaries에 새 행을 쌓는다(읽을 때는 기사별 최신 행). 본문 없는 기사(`no_body`)는 요약하지 않는다.

### 5.2 인사이트 분석 (analyze)

- 입력: 조건(기간·카테고리)에 맞는 기사(본문 없는 기사 제외) 중 최신 40건의 `ID·날짜·카테고리·제목·요약`(요약이 없으면 본문 앞 300자, `analyze_excerpt_chars`)
- 출력 항목(`--items`로 선택, 2개 이상 필수):

| 항목 | JSON 키 | 내용 |
|---|---|---|
| 주요 트렌드 | `trends` | 3~5개, `{title, description, article_ids}` |
| 핵심 키워드 | `keywords` | 5~10개, `{keyword, reason}` |
| 공통점·차이점 | `common_diff` | `{common: [...], differences: [...]}` 카테고리 간(하나뿐이면 기사 간) |
| 시사점 | `implications` | 2~3개 |

- 응답 검사: 요청한 항목이 빠지면 형식 오류(재요청). 트렌드의 근거 기사 ID 중 **입력에 없는 번호는 버리고** WARNING을 남긴다(모델이 만든 ID가 리포트에 실리지 않게). 요청하지 않은 항목은 저장하지 않는다.
- 결과는 `analyses`에 저장하고, `analyze --history`(목록)와 `analyze --show-id N`(상세)으로 다시 볼 수 있다. 이 둘은 API를 부르지 않는다.
- 조건에 맞는 기사가 없으면 API를 부르지 않고 WARNING 후 종료 코드 1.

## 6. CLI 명령

| 명령 | 주요 옵션 | 하는 일 |
|---|---|---|
| `fetch` | `--source electimes`, `--method {rss,crawl,all}`(기본 all), `--feed all\|energy,carbon,economy`, `--category all\|전력,태양광`, `--since YYYY-MM-DD`(그 날 이후 발행 기사만), `--limit 10`(카테고리·피드당, `--since`면 50), `--pages 1`(`--since`면 5), `--recrawl` | RSS 수집 + 세부 카테고리 목록·기사 크롤링 → raw_news. `all`이면 RSS로 찾은 기사의 본문도 크롤링한다. `--since`가 없으면 카테고리마다 최신 N건이라 카테고리별 기사 수가 같아지므로, 카테고리별 비교·일자별 추이를 볼 때는 `--since`를 쓴다 |
| `clean` | `--policy {skip,upsert}`, `--limit`(기사 수), `--rebuild` | raw(`new`) → 검증·정규화·카테고리·중복 처리 → clean_news |
| `summarize` | `--all` \| `--id 1 2 3` \| `--unsummarized`(기본), `--limit 20`, `--force`(이미 요약된 것도 다시) | 기사별 AI 요약 → summaries |
| `analyze` | `--date-from`, `--date-to`, `--category`, `--items trends,keywords,common_diff,implications`, `--max-articles 40`, `--history`, `--show-id` | 기간·카테고리 종합 분석 → analyses, 콘솔 출력 |
| `report` | `--date-from`, `--date-to`, `--category`, `--top 5`, `--format {md,txt}`, `--analysis-id`(기본: 조건이 같은 최신 분석), `--output` | 차트 PNG 3개 + 리포트 콘솔 출력(TXT 형식)·파일 저장. AI를 부르지 않는다 |
| `export` | `--format csv,jsonl,xlsx`, `--status {all,cleaned,summarized,summary_failed,no_body}`(기본 all), `--category`, `--date-from`, `--date-to`, `--include-body`, `--output-dir` | clean_news + 최신 요약 → 파일 |
| `list` (보너스) | `--category`, `--date-from`, `--date-to`, `--keyword`(제목·요약·본문), `--status`, `--page 1`, `--size 10` | 목록 조회 + 페이지네이션 (최신 발행순) |
| `show` (보너스) | `ID`, `--full`(본문 전체) | 기사 상세(메타, 최신 요약·키워드, 요약 실패 기록, 본문 앞부분 500자, raw 수집 이력) |

공통 옵션(서브커맨드 뒤에 붙임): `--config config.json`, `--db data/news.db`, `-v`(DEBUG 로그). 종료 코드: 0 성공, 1 실행 오류(설정·DB·모든 요청 실패), 2 잘못된 옵션, 130 사용자 중단(Ctrl+C, 그때까지 저장한 내용은 유지).

## 7. 시각화와 리포트 (과제 목표 5)

### 7.1 차트 (matplotlib, PNG, `output/charts/`)

| 차트 | 형태 | 집계 |
|---|---|---|
| 카테고리별 뉴스 수 | 가로 막대 | clean_news를 category별로 센다 (조건 적용) |
| 일자별 수집 추이 | 선 2개 | 발행일 기준 기사 수, 수집일 기준 신규 저장 수 |
| (추가) 요약 상태 | 막대 | summarized / cleaned / summary_failed / no_body |

- 한글 폰트는 OS별 후보(`Malgun Gothic` → `AppleGothic` → `NanumGothic`, config `output.chart_fonts`) 중 설치된 것을 고른다. `axes.unicode_minus=False`로 설정한다. 하나도 없으면 WARNING을 남기고 기본 폰트로 그린다(멈추지 않음).
- 파일 이름에는 리포트와 같은 시각을 붙인다: `report_YYYYMMDD_HHMMSS_category.png`, `_daily.png`, `_status.png`.
- 일자별 추이는 첫날부터 마지막 날까지 빈 날을 0으로 채운다. 발행일 선은 "언제 나온 기사인지", 수집일 선은 "언제 우리 DB에 처음 들어왔는지"를 보여 준다.
- 화면이 없는 환경에서도 돌도록 matplotlib `Agg` 백엔드를 쓴다.

### 7.2 리포트 (`output/reports/report_YYYYMMDD_HHMMSS.md|txt`)

리포트는 저장된 데이터만 읽어 만든다(AI를 부르지 않는다). 콘솔에는 TXT 형식으로 출력하고, 파일은 `--format`(기본 md)으로 저장한다. 기사 본문은 싣지 않는다.

1. **조건과 생성 시각**: 기간·카테고리, 대상 기사 수와 발행일 범위, 출처
2. **품질 지표**

| 지표 | 계산 | 기준 |
|---|---|---|
| 수집 성공률 | fetch_log 성공 요청 ÷ (성공 + 실패) | 전체 실행 |
| 정제 통과율 | 검증을 통과한 raw ÷ 정제한 raw (`new` 제외, `rejected`가 아닌 비율) | 전체 실행 |
| 중복 비율 | `duplicate` raw ÷ 정제한 raw | 전체 실행 |
| 본문 확보율 | body_source=`crawl` ÷ 조건 기사 | 조건 기사 |
| 요약 완료율 | summarized ÷ 본문이 있는 기사(`no_body` 제외) | 조건 기사 |
| AI 요약 실패율 | 요약 실패 기록(ai_errors) ÷ (요약 저장 + 요약 실패 기록). 기사 단위 작업 기준이고, 한 작업 안의 재요청 횟수는 세지 않는다 | 조건 기사 |
| 평균 압축률 | 요약 글자 수 합 ÷ 요약에 넣은 본문 글자 수 합 (기사별 최신 요약) | 조건 기사 |

- raw에는 아직 발행일·카테고리가 정해지지 않은 행이 있어서 수집·정제 지표는 조건을 적용하지 않는다(리포트에 기준을 함께 적는다).
- 분모가 0이면 `-`로 표시한다.

3. **TOP N**(`--top`, 기본 5)
   - 카테고리 TOP N: 기사 수
   - 키워드 TOP N: 기사별 최신 요약의 keywords를 기사당 한 번씩 센다. 띄어쓰기·대소문자만 다른 키워드(`한국 전력`·`한국전력`)는 하나로 세고 가장 많이 쓴 표기로 보여 준다.
   - 기자 TOP N: 기자 이름이 없는 기사(`미상`)는 뺀다.
   - 건수가 같으면 이름순.
4. **AI 인사이트**: `--analysis-id`로 지정한 분석, 없으면 조건(기간·카테고리)이 같은 최신 분석. 트렌드의 근거 기사는 제목·링크로 보여 준다.
   - 같은 조건의 분석이 없으면 그 조건 그대로의 `analyze` 명령을 안내하고 WARNING을 남긴다(리포트는 만든다).
   - 지정한 분석의 조건이 리포트 조건과 다르면 그 사실을 리포트에 적는다.
5. **차트**: 7.1의 PNG 3개(MD는 이미지 링크, TXT는 파일 경로)

- 조건에 맞는 기사가 없으면 파일을 만들지 않고 WARNING 후 종료 코드 1.

### 7.3 내보내기 (`output/exports/news_{상태}_YYYYMMDD_HHMMSS.{csv|jsonl|xlsx}`)

- 열: id, published_at, category, category_source, section, title, url, author, methods, status, body_source, summary, keywords, summary_model, summarized_at, first_collected_at, last_collected_at (+ `--include-body`이면 body)
- 요약은 기사별 최신 행. keywords는 JSONL에서는 목록, CSV·XLSX에서는 `; `로 이은 글자.
- CSV는 엑셀에서 한글이 깨지지 않게 BOM이 붙은 UTF-8(`utf-8-sig`)로 쓴다.
- XLSX는 `news` 시트(머리글 고정)와 `info` 시트(생성 시각, 조건, 기사 수, 본문 포함 여부)를 만든다. 엑셀이 받지 않는 제어 문자는 지우고, 한 칸 최대 32,767자로 자른다.
- 조건에 맞는 기사가 없으면 파일을 만들지 않고 WARNING 후 종료 코드 1.

### 7.4 조회 (보너스)

- `list`: 조건(카테고리·기간·키워드·상태)에 맞는 기사를 최신 발행순으로 한 쪽씩 보여 준다. 키워드는 제목·최신 요약·본문에서 찾고 `%`·`_`도 글자 그대로 찾는다. 없는 쪽 번호는 종료 코드 2, 조건에 맞는 기사가 없으면 안내만 하고 0.
- `show ID`: 기사 정보, 최신 요약과 키워드(요약을 여러 번 했으면 횟수), 요약 실패 기록, 본문 앞부분(config `output.show_body_chars`, 기본 500자, `--full`이면 전체), 같은 article_key의 raw 수집 이력(방법·채널·수집 시각·상태·메모). 없는 ID는 종료 코드 2.
- 한글은 화면에서 2칸을 차지하므로 칸을 맞출 때 글자 폭으로 계산한다.

## 8. 설정과 로깅

- `config.json`: 소스 주소·피드·세부 카테고리 코드, 요청 지연·타임아웃·재시도, 수집 상한(`fetch`: 기본 건수·쪽 수, `--since`일 때 건수·쪽 수), 중복 정책, 카테고리 키워드, AI 환경변수 이름·모델·본문 길이 제한, 출력 설정(`output`: TOP N, 리포트 형식, 내보내기 형식, 목록 쪽 크기, show 본문 길이, 차트 폰트 후보), 출력 폴더
- `.env`: API 키 값(저장소에 올리지 않음, `.env.example`만 올림)
- 로깅: 콘솔(INFO 이상, `[INFO] 메시지` 형식)과 `logs/app.log`(DEBUG 이상, 시각·모듈명 포함)
  - INFO: 단계 시작·완료와 건수
  - WARNING: 건너뛴 기사(필드 누락, 본문 없음, 중복), 재시도
  - ERROR: 최종 실패(요청·AI·파싱)

## 9. 오류 처리 정책 (과제 목표 2)

| 상황 | 처리 | 프로그램 |
|---|---|---|
| HTTP 타임아웃(10초)·연결 실패 | 2회 재시도(2초·4초 대기) 후 WARNING, 실패 건수 기록 | 계속 |
| HTTP 4xx/5xx | 404·403 등 4xx는 재시도 없이 기록, 429·5xx는 재시도 | 계속 |
| robots.txt 금지 경로 | 요청하지 않고 WARNING | 계속 |
| robots.txt를 읽지 못함(5xx·연결 실패·401/403) | 그 실행에서는 아무 요청도 하지 않음(404면 제한 없음으로 봄) | 계속(수집 0건) |
| RSS XML 파싱 실패 | 그 피드만 ERROR, 다른 피드는 진행 | 계속 |
| 기사 HTML 구조 변경(본문 없음) | raw에는 저장, clean에서 `no_body` | 계속 |
| AI 호출 실패(타임아웃·429·5xx·400·JSON 형식 오류) | 5절 재요청(한 건당 최대 3번) 후 `ai_errors` 기록, 그 기사만 스킵 | 계속 |
| AI 인증 실패(401·403) | 재요청 없이 ERROR, 그때까지 한 요약은 유지 | 해당 명령만 종료(1) |
| API 키 없음 | 어떤 환경변수가 필요한지 이름만 안내(값은 출력하지 않음) | 해당 명령만 종료(1) |
| 리포트·내보내기 대상 기사 없음 | WARNING, 파일을 만들지 않음 | 해당 명령만 종료(1) |
| 리포트 조건과 같은 AI 분석 없음 | WARNING, 리포트에 `analyze` 실행 방법을 적음 (AI를 대신 부르지 않음) | 계속 |
| 한글 폰트 없음 | WARNING, 기본 폰트로 차트 생성 | 계속 |
| 없는 기사·분석 ID, 없는 쪽 번호, 날짜 역순, 모르는 카테고리·형식 | ERROR로 이유 안내 | 해당 명령만 종료(2) |
| DB 파일 열기 실패 | ERROR | 종료 |

## 11. 테스트 계획

실행: `python -m unittest discover -s tests -t .` (가짜 HTTP 세션과 메모리 DB를 써서 네트워크·API 없이 돈다)

| 대상 | 확인 내용 |
|---|---|
| HTTP 정책 | 404는 재시도 없음, 5xx·타임아웃은 2초·4초 대기 후 재시도, 요청 간 2초, robots.txt 금지·읽기 실패·Crawl-delay |
| 수집 흐름 | RSS + 본문 + 카테고리 크롤링 저장, 두 번째 실행에서 이미 받은 기사 요청 안 함, 깨진 피드는 그 피드만 실패, `--since`: 기간 밖 기사 제외·오래된 기사가 보이면 다음 쪽 요청 안 함·상한에 걸리면 WARNING |
| 정제 | 날짜 형식 통일, 태그·엔티티·바이라인 제거, 필수 필드 누락 → rejected, 본문 없음 → 요약문 대체 |
